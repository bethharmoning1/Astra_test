# 全部 11 任务、每任务 5 轮执行计划

本计划依据远程提交 `fe16862` 更新后的 `CODEX_AGENT.md`，在首个计分 episode 前编写。结果分支为 `test`。2026-10-13 的单次尝试和安装验收不计入本批次。

1. 拉取并合入最新仓库要求，复核已有 CPU 环境、官方配置、允许相机及 runner 归属；复用已验收环境。读取新版完整指南。
2. 由子代理实现独立模型执行器和证据归档工具，父代理复核并调度。根据用户先前提供的 API 授权，优先使用 GPT-6-Astra API 和 `medium`；凭据只在内存加载，不进入代码、请求日志或 Git。模型可用性、图像和工具调用先做基础设施检查，不计为正式任务。
3. 每轮新建模型输入历史，保留本轮全部对话；仅向模型提供冻结指南、工具说明、本轮任务契约、官方选定 RGB 和机器人本体状态。工具只允许当前 episode 的 observe/move/hold/act，禁止任意文件、Shell、历史报告或其他 episode 访问。通过外层程序执行访问限制，而非只要求模型忽略历史。
4. 在计分前冻结指南、模型设置、任务/相机配置、工具协议、提示、异常规则与哈希。初始条件比较使用同任务首轮的允许 RGB 像素逐点完全相同、机器人本体状态绝对误差不超过 1e-8（rtol=0）、相机配置哈希一致；比较只由外部调度者执行，绝不把前轮记录提供给模型。不符合则记录基础设施中断并先排查。
5. 全部任务每任务 5 个有效计分 episode，seed=0。计分前固定最多 3 个不同任务并行，各有独立操作系统进程、短路径 socket、日志和模型历史，不使用或争用默认 runner；同任务各轮串行。每轮新建 label、目录和 runner，完成后 finish/stop 并确认退出。每段动作最多 30 步，每段完成后向模型提供新图像再决策，累计使用当前任务原生上限。只有官方 info.succeed=true 计成功。
6. 可证实的 API/网络/文件/进程故障先在同轮重试瞬时请求，不重复已执行动作；无法恢复则标记 interrupted，保留全部证据。问题修复且冻结配置未变化时，独立上下文从 seed=0 为该计分轮补测，记录 replacement_of。模型动作错误、策略失败、放弃或原生超时计失败，不能补跑替换成绩。若需改动冻结策略或工具语义，结束原批次、另建批次。
7. 每次尝试结束即归档完整 manifest/events/summary/全部 obs-*、命令请求与返回、时间/退出码、独立 runner 日志、模型公开请求响应、dispatch、初始条件核验、audit 和文件 SHA-256 清单。无权限导出的模型内部推理明确标记不可获取，不假称完整。预览 token 和凭据脱敏须记录映射。
8. 每轮结束后由单一外部调度者串行更新全部 11 任务进度表与逐次尝试 CSV，核验所有证据被 Git 跟踪，提交并推送 `test`；核对远程提交。不同任务的模型不会获知这些进度或归档。全部 55 个有效计分 episode 完成后才发布正式总体成功率。
